\section{Portability}
\label{sec:discussion}

\sys is designed for portability, though our current implementation targets NVIDIA's GPU stack due to its widespread production use. NVIDIA’s production drivers bypass Linux’s standard kernel interfaces, complicating immediate portability. On the host side, our design conceptually aligns with generic Linux abstractions: for memory management, we follow Linux's Heterogeneous Memory Management (HMM) and its \texttt{migrate_vma} interface, already adopted by AMD ROCm with XNACK retryable faults; for scheduling, we abstract GPU queues based on Linux DRM scheduler’s \texttt{drm_sched_entity}, mapping directly to NVIDIA’s TSGs and potentially AMD’s user-mode queues, whose scheduling parameters (e.g., \texttt{HWS}, \texttt{HWS_NO_OVERSUBSCRIPTION}) are enforced by vendor firmware during HQD mapping~\cite{rocm-gpu-memory,linux-gpusvm-doc,drm-gpu-sched,amdgpu-userq-doc}. On the device side, our compiler generates vendor-neutral eBPF bytecode using SPIR-V, enabling future compatibility with compute runtimes such as AMD ROCm and Intel Level Zero. However, end-to-end portability requires vendor-specific runtime support, instrumentation hooks, and hardware-specific performance tuning, which remain future work~\cite{spirv-ir-rfc,llvm-offload-design}.
