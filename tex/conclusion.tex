\section{Conclusion}
\label{sec:conclusion}
We presented \sys, a unified, verifier-backed policy runtime that treats the GPU driver and device execution environment as a single programmable subsystem. By exposing stable attach points for memory placement and scheduling, executing the same restricted eBPF IR on host and device, and sharing state through unified-memory-backed BPF maps, \sys enables bcc-style observability and adaptive policies with low overhead. Across PyTorch, \texttt{llama.cpp}, vLLM, and Faiss, \sys-based policies transparently improve throughput by up to $5\times$ and reduce tail latency by up to $2\times$ relative to static heuristics, while instrumentation-only deployments average $2$–$3\%$ overhead. We see \sys as a practical foundation for policy-driven GPU management that brings the benefits of kernel-anchored programmability to modern GPU datacenters.
