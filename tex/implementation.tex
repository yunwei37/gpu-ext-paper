
\section{Implementation}
\label{sec:implementation}

We implemented \sys on Linux 6.15, extending the OS kernel with a standalone file ($\sim$1 KLOC) that handles hook registration and verifier extensions. We integrated lightweight instrumentation ($\sim$100 LOC) into NVIDIA's open GPU OS kernel modules to expose memory and scheduling state transitions as GPU-specific kfuncs (\S\ref{sec:impl-host}). Our user-space loader and JIT infrastructure ($\sim$10 KLOC) builds upon bpftime's framework~\cite{bpftime} for device-side code generation, while an LLVM-based backend ($\sim$1 KLOC) translates the restricted \sys eBPF instruction subset into GPU device code (PTX) (\S\ref{sec:impl-gpu}).
Although our implementation targets NVIDIA GPUs, the host-side design aligns with generic Linux abstractions (HMM/\texttt{migrate\_vma}~\cite{rocm-gpu-memory,linux-gpusvm-doc}, DRM scheduler~\cite{drm-gpu-sched,amdgpu-userq-doc}), and the device-side can be extended to generate vendor-neutral IR~\cite{spirv-ir-rfc} for future portability.

\subsection{Host-side Integration}
\label{sec:impl-host}
\paragraph{Memory State-Transition Hooks}
\sys extends the NVIDIA Open GPU OS Kernel Modules~\cite{nvidia-open-gpu}, instrumenting UVM at \emph{activate}, \emph{access}, \emph{evict\_prepare}, and \emph{prefetch} hooks. The driver constructs the callback context and retains resource ownership and eviction authority. Root-chunk reordering operates at 2MB granularity; prefetch requests select page-granularity regions within the validated VA-block bounds. In the revised interface, \texttt{bpf\_gpu\_set\_prefetch\_region} records wide endpoints and \texttt{bpf\_gpu\_request\_reorder} records a destination and position. Neither setter directly changes a list or starts a migration. Driver code checks the recorded decision before applying the native operation (\S\ref{sec:verification}); direct writes to protected BTF context state are denied. The unsafe raw VA-space migration helper is no longer exposed by this validated interface.

\paragraph{Scheduling Hooks}
Time-Slice Group (TSG) hooks cover initialization and teardown. Initialization exposes immutable inputs; \texttt{bpf\_\allowbreak{}nv\_\allowbreak{}gpu\_\allowbreak{}set\_\allowbreak{}timeslice} and \texttt{bpf\_\allowbreak{}nv\_\allowbreak{}gpu\_\allowbreak{}set\_\allowbreak{}interleave} record requests in driver-private state for validation before native setters. The 575 implementation also validates persistent timeslice decisions inside the existing authorized RM control path. Preemption requests use \texttt{bpf\_\allowbreak{}nv\_\allowbreak{}gpu\_\allowbreak{}preempt\_\allowbreak{}tsg} from a sleepable BPF context, including a workqueue callback. These paths preserve native actuation rather than allowing arbitrary scheduler-state writes.

\subsection{GPU Runtime}
\label{sec:impl-gpu}

\paragraph{Verification and JIT Compilation}
Kernel-loaded host programs use Linux's eBPF verifier. The GPU safety prototype instead runs PREVAIL, uniformity analysis, and SIMT checks (\S\ref{sec:verification}) before the loader forwards device bytecode to the PTX backend. Helper and map descriptions determine their modeled effects; these are not inferred solely from BTF annotations. Attachment rejection requires \texttt{ENABLE\_EBPF\_VERIFIER} and strict mode; the current revision's performance runtime does not enable that check. JIT compilation can inline helpers and map accesses. Compared with the workshop implementation~\cite{egpu}, warp aggregation reduces duplicated work, but it is not a blanket prohibition of atomics or cross-SM coordination.

\paragraph{Device-Side State-Transition Hooks}
\sys hooks device-side state transitions (GPU kernel launch, memory access, execution-phase boundaries) by using ptrace to pause applications, intercepting CUDA runtime APIs, extracting GPU kernel PTX, inserting binary trampolines, and reloading instrumented GPU kernels without application recompilation or restart. Trampolines insert prologue/epilogue logic for SIMT register preservation. In each trampoline, per-lane inputs are aggregated using \texttt{\_\_ballot\_\allowbreak{}sync} and \texttt{\_\_shfl\_\allowbreak{}sync}, with a warp leader selected via \texttt{\_\_ffs\allowbreak{}(\_\_active\-mask())} to execute the scalar eBPF handler once per warp, broadcasting results via shuffle instructions. For block-level scheduling, \sys implements policies using persistent GPU kernels that poll and claim logical work units; on Blackwell GPUs, we use cluster launch control APIs~\cite{cuda-clc} to schedule thread blocks. For memory observation, \sys attaches eBPF handlers at memory instructions, GPU kernel function boundaries, and tracepoints to capture access patterns and issue policy hints to the host driver via cross-layer maps (e.g., device L2 prefetch can trigger a host callback for extended prefetch).

\paragraph{Hierarchical Maps and Cross-Domain State}

Cross-layer state (\S\ref{sec:cross-layer-maps}) uses GPU-accessible host memory, GPU global memory, and local aggregation according to the selected map and hook. Warp-local counters can reduce shared updates, but synchronization requirements depend on the map implementation and its readers. Publishing device observations to the host has a cost and may expose stale summaries; neither coherent snapshots without synchronization nor universal avoidance of GPU atomics follows from hierarchical placement.
