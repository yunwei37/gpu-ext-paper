\keywords{GPU resource management, eBPF, kernel extensibility, memory management, scheduling, unified virtual memory}

\begin{abstract}
GPU resource management policies significantly influence application performance, yet optimal policies vary widely across workloads and deployment scenarios. Existing user-space solutions offer programmability and flexibility but lack cross-tenant visibility and hardware-level control, while kernel-driver modifications introduce complexity and safety risks, limiting deployment and AI agent policy exploration.
We introduce \sys, an OS interface for GPU resource management that resolves this tradeoff through safe, programmable eBPF extensions across the GPU kernel driver and device. Unlike existing CPU-focused policy interfaces which rely on synchronous callbacks and local resource control, \sys addresses GPU-specific challenges: high latency of cross-device coordination, coupling of memory management and scheduling decisions, and limited device observability. To overcome these, \sys models GPU resource management as programmable asynchronous effects on resource lifecycles, directed by verified eBPF programs and decoupling policy triggers from lifecycle transitions across the boundary. To further bridge the visibility gap, \sys enables safe eBPF execution directly on GPU hardware with a SIMT-aware verifier. Evaluated on the Linux NVIDIA GPU driver, \sys with AI-generated policies improves throughput by 1.76× over application-tuned baselines and reduce tail latency by up to 2×, without application modifications or compromising stability.
\end{abstract}
