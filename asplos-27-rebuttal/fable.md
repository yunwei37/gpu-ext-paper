## 4. Author Response 
 
We thank all reviewers. The main requests—SOTA research baselines (E,F), safety depth (B,F), and attribution (F)—are answered below with evidence already in the paper.
 
**SOTA research baselines (E,F).** Two SOTA comparisons already exist; we will foreground them. (1) GPREEMPT [14] (ATC'25), a SOTA driver-modification scheduler: we expressed its priority-timeslice policy as a 925-LOC gpubpf program, zero driver-source changes, achieving its intended benefit (LC P99 −96%, Fig.12). (2) LMCache [9], a SOTA KV-cache framework: gpubpf matches its throughput with better tail latency (Fig.9). Driver-level systems (TimeGraph/Gdev/GCAPS/LithOS) are mechanism-level alternatives requiring unsafe driver modification and restarts; the comparable axis is whether their policies are expressible on gpubpf—the GPREEMPT-equivalent result above shows they are. E's cited MoE system (arXiv:2303.06182) migrates experts as atomic units at framework level via gating outputs, requiring runtime integration; its gating-based prediction is itself expressible as a gpubpf uprobe policy on the gating function; we commit to implementing this gating-aware policy and comparing directly in revision. gpubpf already predicts activations gating-free via device-side stride tracing, at page granularity (finer overlap—per E).
 
**Safety of an asynchronous mechanism (B, F-W4/Q3).** Two independent layers. (1) Program safety: the unmodified Linux verifier (termination, memory safety, restricted kfuncs) plus SIMT-aware passes—branches, loop bounds, and map keys must be warp-uniform; barriers, global synchronization, and non-uniform atomics are forbidden; per-hook resources are bounded (§3.5.1). (2) Transition validity: callbacks never mutate state; they enqueue transition requests on driver-owned state machines, which validate each request against current state; stale or conflicting requests degenerate into no-ops or reordering—never invalid states (§3.4); we will surface this in §1. Asynchrony affects optimality, not integrity; FIFO fallback under pressure or misconfiguration. Empirically: 59 agent-generated policies, 974 runs, 50 safety events (24 logic, 18 performance, 2 verifier-rejected, 2 GPU-verifier overflows, 4 other), zero panics or corruption. Revision adds an event taxonomy, verifier-rejection examples (lane-varying branches; unbounded eviction-list loops), and failure-mode analysis; TCB in §3.5.
 
**Mechanism vs. policy attribution (F-W3/Q2).** Fig.13 already separates them: on memory-bound multi-tenant workloads, the GPREEMPT-style scheduling policy (expressible today) yields <1%, while gpubpf memory policies (impossible in user space, unsafe as driver patches) yield 55–92%. Fig.7a isolates device-side hooks (1.34×→1.77× combined); cudaMemAdvise captures part of the decode gain but needs app changes and costs 40% prefill (Fig.8). We will add a table mapping each policy to {user-space / driver-mod / gpubpf-only}.
 
**Multi-tenancy (E-W1, D3).** We agree inference rarely uses MIG—this supports our motivation: §2.3 cites MIG as inflexible static partitioning; our experiments use no MIG; they target the software co-location operators actually deploy (Fig.14: LC TPOT −40–45% while BE improves 28%). Per-tenant policies (D3): per-cgroup attachment, verifier-enforced map namespacing, per-tenant hook budgets; the driver arbitrates cross-tenant transitions; single-policy design mirrors sched_ext.
 
**Per-reviewer.** A1: policies adapt to observed composite behavior—our KV-cache agent detected thrashing against vLLM's allocator and converged to region-differentiated prefetch; instant detachment bounds pathologies. A2: host-side policies need no PTX; device hooks need PTX in fatbins (common for JIT compatibility); SASS patching is feasible future work. A3: shards hold associative aggregates; the eviction list is host-authoritative; non-composable global state can pin maps host-side at PCIe cost (Fig.15b). A4: agreed—we will discuss verified state-transitions as an abstraction future accelerators could expose natively (architected attach points, firmware-validated transition tables, privileged telemetry). A5: NVBit toolchain constraints required P40; RTX 5090 numbers will be added. D1: staleness affects optimality only; snapshots merge at kernel completions; policies rate-limit via PCIe-utilization guards (as our KV policy does); we will add sync-interval sensitivity data. D2: CXL adds tier states/transitions atop HMM/migrate_vma; model unchanged. D4: overhead is per-warp (leader executes, shuffle broadcast), independent of block count—3–14% on llama.cpp prefill (Table 1); we will add grid-scaling data. D/F (ptrace, coupling, portability): ptrace attach is one-time (273ms), only for device hooks; LD_PRELOAD suits production; driver-hook policies touch no application; host hooks: ~100 LOC over the open GPL modules, aligned with HMM/migrate_vma and DRM abstractions; SPIR-V backend path (§4). 

E-Q1: the state machine adds a storage tier; ms-scale transfers fit the async model; a cuFile/GDS kfunc would select demotion targets—complementary to Weka/VAST/CMX (transport); gpubpf supplies cross-tier placement policy. 

E (agent): we will release prompts and agent interations as artifacts. 

F-W1: the revision expands §3.4/§4 with transition-validation pseudocode and the SIMT-verifier algorithm.
